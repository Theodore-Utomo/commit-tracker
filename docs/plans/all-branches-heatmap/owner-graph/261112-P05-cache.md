# Plan: Cache and Incremental Sync

Date: 2026-11-12
Status: Pending

## Summary

Remember the last result for a viewer, a profile, and a mode, and only ask GitHub for commits newer than that result. Done means a second look at the same profile is fast, a day-old cache refreshes from the last sync, and "Clear cache" forces the next look to start over.

## Acceptance Criteria

- A miss, a `schemaVersion` other than `1`, or the fetch after Clear cache lists repos and fetches with `since` equal to the grid start.
- Every cache hit calls `listOwnerRepos`, `getBranchCommits`, and `getMergedPrCommits`. History `since` is the stored `lastSync` timestamp. The merged-PR search uses the `YYYY-MM-DD` of that timestamp in UTC. The grid start is not used on a hit. Age is `Date.now() - Date.parse(contributions.fetchedAt)`.
- Two overlapping requests for the same viewer, profile, and mode share one in-flight promise.
- Clear cache deletes every record. The options button sends `CLEAR_CACHE` and does not open IndexedDB. A `put` from a `GET_CONTRIBUTIONS` that started before the clear does not write after the clear.
- A `partial: true` result is returned and not written.
- `pnpm test -- --run` passes, including the new cases in Unit Tests.

## Privacy

The cache key is `{ viewerLogin, profileLogin, mode, schemaVersion: 1 }`. This phase only writes `mode: 'owner'`. A read must pass the same viewer and mode. The content script still never sees the raw record, only `Contributions`.

## Messages

- `{ type: 'CLEAR_CACHE' }` with success `{ ok: true, data: { cleared: true } }` and failure `UNKNOWN` if IndexedDB rejects.

Database name `commit-tracker`, object store `entries`. The value is `{ contributions, lastSync, schemaVersion }`. Miss and hit both end in the same `Contributions` object: `dedupeCommits`, `policyFor('owner')`, then `aggregateByDay`. `days[date].commits` is the commits counted into that day, and that object is what `put` stores. `lastSync` is the greatest `authoredDate` among those commits, or `fetchedAt` when there are none. On a hit, flatten those stored commits, concatenate the commits just fetched, and run that same sequence. `partial: true` still skips `put`. Schema version other than `1` is a miss. The content script opens a `browser.runtime.connect` port before `sendMessage` and disconnects when the response arrives. `{ ok: false, error: 'UNKNOWN' }` from clear cache shows "Could not clear the cache."

## Task Order

3. **Worker and options** — Add the in-flight map, `CLEAR_CACHE`, the options button, and the keepalive port.

## Subagent Takeaways

- **plan-simplifier**: The in-flight map stays on the worker. The overlapping-request test moved to the handler test.
- **plan-scope-guard**: No material findings. The index now depends on the heatmap phase as well as merged pull requests, so `index.tsx` exists.
- **plan-scrutinizer**: A cache hit still asks for commits newer than `lastSync`. It does not skip GitHub for 24 hours. Clear cache cannot be undone by a write that started earlier. A second pass requires the stored `days[date].commits` to be the source of the next merge, so a later visit keeps the year already fetched.
- **plan-compliance-audit**: No material findings. The cache key includes viewer, profile, and mode.
