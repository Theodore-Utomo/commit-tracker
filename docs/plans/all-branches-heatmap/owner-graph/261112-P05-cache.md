# Plan: Cache and Incremental Sync

Date: 2026-11-12
Status: Pending

## Summary

Remember the last result for a viewer, a profile, and a mode, and ask GitHub only for the recent window instead of the whole year. Done means a second look at the same profile is fast, a commit pushed days after it was written is still found, the year rolls forward without keeping old commits, and "Clear cache" forces the next look to start over.

## Acceptance Criteria

- A miss, a `schemaVersion` other than `1`, or the fetch after Clear cache lists repos and fetches with `since` equal to the grid start.
- Every cache hit calls `listOwnerRepos`, `getBranchCommits`, and `getMergedPrCommits`. There is no freshness window that skips GitHub.
- On a hit, `since` is `max(gridStart, lastSync − 14 days)`. History uses that timestamp. The merged-PR search uses the UTC `YYYY-MM-DD` of that same timestamp.
- `lastSync` is the time the fetch started, captured before its first GraphQL call. It is not derived from commit dates.
- A commit whose `authoredDate` is before the previous `lastSync`, but which the fake client first returns on the next hit (pushed late), is counted. A commit already in the cache and returned again by the overlap window still counts once.
- On a hit, a stored commit whose local day is now before the grid start is not in `days` or `totals`.
- Two overlapping requests for the same profile share one in-flight promise.
- Clear cache deletes every record and drops every in-flight entry. The options button sends `CLEAR_CACHE` and does not open IndexedDB. A `put` from a `GET_CONTRIBUTIONS` that started before the clear does not write after the clear. A request made after the clear does not join a promise that started before it.
- A `partial: true` result is returned and not written.
- `pnpm test -- --run` passes, including the new cases in Unit Tests.

## Privacy

The cache key is `{ viewerLogin, profileLogin, mode, schemaVersion: 1 }`, with both logins lowercased. This phase only writes `mode: 'owner'`. A read must pass the same viewer and mode. The content script still never sees the raw record, only `Contributions`.

## Messages

- `{ type: 'CLEAR_CACHE' }` with success `{ ok: true, data: { cleared: true } }` and failure `UNKNOWN` if IndexedDB rejects. The listener uses `sendResponse` and `return true`, like `GET_CONTRIBUTIONS`.

Database name `commit-tracker`, object store `entries`. The value is `{ contributions, lastSync, schemaVersion }`.

**Sync window.** Capture `startedAt = now()` before the first GraphQL call. On a miss, `since` is the grid start. On a hit, `since` is the later of the grid start and `lastSync − 14 days`. Git's `since` filter compares commit dates, not push times, so a commit written on Monday and pushed on Friday has an old date when it arrives. The 14-day overlap catches those, and dedupe by SHA absorbs the repeats. A commit pushed more than 14 days after its commit date is only found after Clear cache; that limit is accepted. After a successful, non-partial result, store `lastSync = startedAt`.

**Merge.** Miss and hit both end in the same `Contributions` object: `dedupeCommits`, `policyFor('owner')`, the grid-year filter, then `aggregateByDay`. On a hit, flatten the stored `days[date].commits`, concatenate the commits just fetched, and run that same sequence. The grid-year filter uses the current `gridDays(today)`, so days that have rolled out of the year are dropped. `days[date].commits` is the commits counted into that day, and that object is what `put` stores. `partial: true` still skips `put`. A schema version other than `1` is a miss.

**In-flight and clear.** `handle-message.ts` holds `inFlight: Map<string, Promise<Response>>`, keyed by the lowercased profile login, and a numeric `generation`. A request records the generation when it starts. `CLEAR_CACHE` increments the generation, empties `inFlight`, then calls `clear()`. Before its `put`, a request compares its recorded generation with the current one and skips the write if they differ. Losing this map when the worker stops is harmless.

`{ ok: false, error: 'UNKNOWN' }` from clear cache shows "Could not clear the cache." on the options page. The keepalive port already exists from the branch-commits phase.
