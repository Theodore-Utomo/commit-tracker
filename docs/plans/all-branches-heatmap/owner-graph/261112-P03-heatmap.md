# Plan: Year Heatmap

Date: 2026-11-12
Status: Pending

## Summary

Replace the commit total with a year-long heatmap drawn next to GitHub's graph, and ask before fetching. Done means the viewer accepts a prompt, sees "All commits across branches", and the squares use GitHub's own contribution colors in light and dark mode.

## Acceptance Criteria

- The prompt appears beside the graph when it is half visible. Nothing is fetched before Accept.
- "Always show" in the options page skips the prompt on the next visit and fetches immediately.
- The content script reads display preferences only from `src/services/preferences.ts`, which holds no token code. The built content script (`.output/chrome-mv3/content-scripts/*.js`) contains no reference to the token storage key.
- The heatmap has 53 columns and 7 rows, starting on the grid's Sunday. Empty days are level 0. A day with commits uses levels 1–4.
- Days with the same positive count share a level. A single distinct positive count uses level 1, not level 4.
- Squares use `var(--contribution-default-bgColor-0)` through `var(--contribution-default-bgColor-4)`.
- The heading text is exactly `All commits across branches`.
- `pnpm test -- --run` passes, including the new cases in Unit Tests.
- `pnpm test:e2e` passes when `E2E_GITHUB_TOKEN` is set: the test learns the viewer login from `GET https://api.github.com/user`, saves the token through the options page, opens that profile, accepts the prompt, and finds the heading.

## Privacy

Still owner mode only. The prompt is shown on every profile, but Accept on someone else's profile keeps today's `{ viewerLogin }` behavior and does not draw a heatmap. The automatic fetch from the previous phase is removed.

## Messages

While that read is unsettled, do not mount the prompt and do not send. If the stored value is true, send one `GET_CONTRIBUTIONS` for `getProfileLogin(location.href)` and do not mount the prompt. Compare against the login captured when the request was sent, not a field on the response; failures and `{ viewerLogin }` carry no profile login. Keep the phase 1 observer setup. Do not leave the previous profile's heatmap mounted.

`colorLevels` reads one count per grid day. The content script builds that array with `gridDays` of the local civil today and `contributions.days[date]?.count ?? 0`. Column `col`, row `row` (Sunday at the top) uses `dates[col * 7 + row]`. Level 0 is count 0. Let `distinct` be the positive counts with duplicates removed, sorted ascending, and `n` its length. A count at index `i` in `distinct` has level `1 + Math.floor((i * 4) / n)`. This gives level 1 when `n` is 1, and never exceeds 4. Equal counts share an index, so they share a level. `Heatmap` renders an SVG of 53 by 7 rects. `createShadowRootUi` mounts the prompt and the heatmap in one shadow root with `cssInjectionMode: 'ui'`, as the next sibling of the graph container. `playwright.config.ts` already points at `tests/e2e`. The spec runs `pnpm build`, then launches Chromium with `--load-extension` pointed at `.output/chrome-mv3`. It fails when `E2E_GITHUB_TOKEN` is missing, and the failure names that variable. The locator pierces the open shadow root. The test fails if `api.github.com/graphql` is called before the Accept click. It then clicks `See commits across all branches` and expects the heading and 371 rects.

The GraphQL calls come from the service worker, so `page.route` and page request events never see them. The spec sets `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1` before launch and records requests with `context.on('request')`. It asserts zero GraphQL requests before Accept and at least one after, so the check cannot pass while blind. If the installed Playwright version doesn't report worker requests with the flag set inside the spec, set it in the `test:e2e` script instead. Do not drop the assertion.

The spec handles a real token, so:

- `test.use({ trace: 'off', screenshot: 'off', video: 'off' })` at the top of the spec. A trace would record the typed token.
- The persistent context uses a fresh `fs.mkdtemp` directory, removed in `afterAll`.
- The token is never printed, never placed in a test title or assertion message, and never written to a file.

The content script keeps the keepalive port from the branch-commits phase.

`src/services/preferences.ts` holds the display preferences that the page needs (`alwaysShow` now, `showAllBranches` later). It imports nothing from `settings.ts`. The content script may import `preferences.ts` and must never import `settings.ts`, which holds the token and the commit emails. The options page may import both. Add `preferences.ts` to the project structure in CLAUDE.md section 6.
