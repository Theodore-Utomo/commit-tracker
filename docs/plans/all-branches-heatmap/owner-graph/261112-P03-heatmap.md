# Plan: Year Heatmap

Date: 2026-11-12
Status: Pending

## Summary

Replace the commit total with a year-long heatmap drawn next to GitHub's graph, and ask before fetching. Done means the viewer accepts a prompt, sees "All commits across branches", and the squares use GitHub's own contribution colors in light and dark mode.

## Acceptance Criteria

- The prompt appears beside the graph when it is half visible. Nothing is fetched before Accept.
- "Always show" in the options page skips the prompt on the next visit and fetches immediately.
- The heatmap has 53 columns and 7 rows, starting on the grid's Sunday. Empty days are level 0. A day with commits uses levels 1–4.
- Days with the same positive count share a level. A single distinct positive count uses level 1, not level 4.
- Squares use `var(--contribution-default-bgColor-0)` through `var(--contribution-default-bgColor-4)`.
- The heading text is exactly `All commits across branches`.
- `pnpm test -- --run` passes, including the new cases in Unit Tests.
- `pnpm test:e2e` passes when `E2E_GITHUB_TOKEN` is set: the test learns the viewer login from `GET https://api.github.com/user`, saves the token through the options page, opens that profile, accepts the prompt, and finds the heading.

## Privacy

Still owner mode only. The prompt is shown on every profile, but Accept on someone else's profile keeps today's `{ viewerLogin }` behavior and does not draw a heatmap. The automatic fetch from the previous phase is removed.

## Messages

No new message types. On a profile URL, wait until the contribution graph is at least half visible. Read `alwaysShow` before mounting. While that read is unsettled, do not mount the prompt and do not send. If the stored value is true, send one `GET_CONTRIBUTIONS` for `getProfileLogin(location.href)` and do not mount the prompt. Otherwise mount the prompt and send only from the Accept button, whose accessible name is `See commits across all branches`. Accept stays disabled until the response settles, and the shadow tree shows `Loading commits…`. A non-ok response shows the error code, and `RATE_LIMITED` also shows `resetAt`. `{ viewerLogin }` does not draw a heatmap.

On `turbo:load`, unmount the shadow UI, disconnect the observers, and ignore a response whose login is not the current profile. Keep the phase 1 observer setup. Do not leave the previous profile's heatmap mounted.

`colorLevels` reads one count per grid day. The content script builds that array with `gridDays` of the local civil today and `contributions.days[date]?.count ?? 0`. Column `col`, row `row` (Sunday at the top) uses `dates[col * 7 + row]`. Level 0 is count 0. If every positive count is the same number, those days are level 1. Otherwise sort the distinct positive counts and assign levels 1–4 by which quarter of that list the count falls in. The same count always shares the lower level. `Heatmap` renders an SVG of 53 by 7 rects. `createShadowRootUi` mounts the prompt and the heatmap in one shadow root with `cssInjectionMode: 'ui'`, as the next sibling of the graph container. `playwright.config.ts` already points at `tests/e2e`. The spec runs `pnpm build`, then launches Chromium with `--load-extension` pointed at `.output/chrome-mv3`. It fails when `E2E_GITHUB_TOKEN` is missing, and the failure names that variable. The locator pierces the open shadow root. The test fails if `api.github.com/graphql` is called before the Accept click. It then clicks `See commits across all branches` and expects the heading and 371 rects.
