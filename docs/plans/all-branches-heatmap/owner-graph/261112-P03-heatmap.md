# Plan: Year Heatmap

Date: 2026-11-12
Status: In Progress

## Summary

Replace the logged total with a year-long heatmap drawn next to GitHub's graph, and ask before fetching. Done means the viewer accepts a prompt, sees "All commits across branches", and the squares use GitHub's own contribution colors in light and dark mode.

## Acceptance Criteria

- The prompt appears beside the graph when it is half visible. Nothing is fetched before Accept.
- "Always show" in the options page skips the prompt on the next visit and fetches immediately.
- After any response settles, Accept is enabled again, so a failure can be retried. With "Always show" on, a failure mounts the prompt so Accept can retry.
- The content script reads display preferences only from `src/storage/preferences.ts`, which holds no token code. ESLint rejects an import of `src/services/` from the content script, `src/ui/`, or `src/dom/`. The built content script (`.output/chrome-mv3/content-scripts/*.js`) does not contain `githubToken`.
- The heatmap has 53 columns and 7 rows, starting on the grid's Sunday. Empty days are level 0. A day with commits uses levels 1–4.
- Days with the same positive count share a level. A single distinct positive count uses level 1, not level 4.
- Squares use `var(--contribution-default-bgColor-0)` through `var(--contribution-default-bgColor-4)`.
- The heading text is exactly `All commits across branches`.
- `pnpm test -- --run` passes, including the new cases in Unit Tests.
- `pnpm test:e2e` passes when `E2E_GITHUB_TOKEN` is set: the test learns the viewer login from `GET https://api.github.com/user`, saves the token through the options page, opens that profile, accepts the prompt, and finds the heading.

## Privacy

Still owner mode only. The prompt is shown on every profile, but Accept on someone else's profile keeps today's `{ viewerLogin }` behavior and draws nothing. That in-between state is expected; the privacy-modes phase draws other profiles. The automatic fetch from the previous phase is removed.

## Messages

No new message types. On a profile URL, wait until the contribution graph is at least half visible. Read `alwaysShow` before mounting. While that read is unsettled, do not mount the prompt and do not send. If the stored value is true, send one `GET_CONTRIBUTIONS` for `getProfileLogin(location.href)` and do not mount the prompt. Otherwise mount the prompt and send only from the Accept button, whose accessible name is `See commits across all branches`. Accept stays disabled while a request is open, and the shadow tree shows `Loading commits…`. On `turbo:load`, unmount the shadow UI, disconnect the observers, and ignore any response, success or failure, whose request was sent for a login other than the current profile. Compare against the login captured when the request was sent, not a field on the response; failures and `{ viewerLogin }` carry no profile login. Keep the phase 1 observer setup. Do not leave the previous profile's heatmap mounted.

**Levels.** Level 0 is count 0. Let `distinct` be the positive counts with duplicates removed, sorted ascending, and `n` its length. A count at index `i` in `distinct` has level `1 + Math.floor((i * 4) / n)`. This gives level 1 when `n` is 1, and never exceeds 4. Equal counts share an index, so they share a level.

**Heatmap.** `Heatmap` takes `contributions` and `today` (the local civil date) as props. It calls `gridDays(today)`, builds one count per date from `contributions.days[date]?.count ?? 0`, and calls `colorLevels`. Column `col`, row `row` (Sunday at the top) uses `dates[col * 7 + row]`. It renders an SVG of 53 by 7 rects. The entrypoint only passes props.

**Mounting.** `createShadowRootUi` mounts the prompt and the heatmap in one shadow root with `cssInjectionMode: 'ui'`, `anchor: findContributionGraph(document)`, and `append: 'after'`, so the host is the graph's next sibling and hiding the graph later never hides the host.

**Preferences module.** `src/storage/preferences.ts` holds the display preferences that the page needs (`alwaysShow` now, `showAllBranches` later). It may import WXT `storage` and `src/core/` only. It never imports `src/services/`. The content script, `src/ui/`, and the options page may import it. `src/services/settings.ts` keeps the token and the commit emails, and the content script never imports it. `eslint.config.js` adds `no-restricted-imports` with a pattern for `**/services/**`, applied to `src/entrypoints/github-profile.content/**`, `src/ui/**`, and `src/dom/**`. Add `src/storage/` to CLAUDE.md section 6 and to the Layers table and import rules in `docs/reference/quick-reference.md`.

**End to end.** `playwright.config.ts` already points at `tests/e2e`. The spec runs `pnpm build`, then launches Chromium with `--load-extension` pointed at `.output/chrome-mv3`. It fails when `E2E_GITHUB_TOKEN` is missing, and the failure names that variable. The locator pierces the open shadow root. The GraphQL calls come from the service worker, so `page.route` and page request events never see them. The `test:e2e` script sets `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1`, and the spec records requests with `context.on('request')`. It asserts zero GraphQL requests before Accept and at least one after, so the check cannot pass while blind. It then expects the heading and 371 rects.

The spec handles a real token, so:

- `test.use({ trace: 'off', screenshot: 'off', video: 'off' })` at the top of the spec. A trace would record the typed token.
- The persistent context uses a fresh `fs.mkdtemp` directory, removed in `afterAll`.
- The token is never printed, never placed in a test title or assertion message, and never written to a file.

The content script keeps the keepalive port from the branch-commits phase.
